# 数据库表结构

本文档给技术和 AI 阅读，方便代码审查和 Git diff。业务核对字段时优先查看 `docs/数据库表结构.xlsx`。

## 维护规则

- SQL 初始化源头：`backend/db/init/001_schema.sql`
- 已有数据库升级：`backend/db/migrations/*.sql`
- 技术/AI 文档：`docs/数据库表结构.md`
- 业务核对表：`docs/数据库表结构.xlsx`

新增或修改表结构时，以上四处必须同步。不能只改 SQL，也不能只改 Excel。

## 设计约定

- 数据库：PostgreSQL
- 表名前缀：`pms_`
- 主键：默认使用 `id BIGSERIAL PRIMARY KEY`
- 删除标记：业务主表默认使用 `is_deleted SMALLINT`，`0` 正常，`1` 删除
- 时间字段：统一使用 `TIMESTAMPTZ`，默认 `NOW()`
- 接口返回：后端字段保持数据库命名，前端 API 层转换为页面 record

## pms_work_order 运维工单表

| 字段 | 类型 | 约束/默认值 | 说明 |
|---|---|---|---|
| `id` | `BIGSERIAL` | 主键 | 数据库主键 |
| `product_id` | `BIGINT` | 必填，引用 `pms_product.id` | 所属产品，新增和变更时必须为启用状态 |
| `problem_type` | `BIGINT` | 必填，引用 `pms_archive.id` | 问题类型档案，新增和变更时必须为启用的 `PT` 类型 |
| `problem_desc` | `TEXT` | 必填 | 问题描述 |
| `result_desc` | `TEXT` | 可空 | 处置结果 |
| `activation_reason` | `TEXT` | 被激活时必填，最多 100 字 | 本轮激活原因；进入待处理或处理中时清空，再次激活时更新 |
| `follower_id` | `BIGINT` | 必填，引用 `pms_user.id` | 跟进人 |
| `urgency` | `SMALLINT` | 默认 `1` | 紧急程度 |
| `status` | `SMALLINT` | 默认 `0` | 工单状态：`0` 待处理、`1` 处理中、`2` 已解决、`3` 已关闭、`4` 已暂停、`5` 被激活；已解决或已关闭可激活，被激活后只能重新解决 |
| `is_overdue` | `SMALLINT` | 默认 `0` | 是否逾期 |
| `expected_resolve_date` | `TIMESTAMPTZ` | 可空 | 期望解决时间 |
| `resolve_date` | `TIMESTAMPTZ` | 可空 | 解决时间 |
| `close_date` | `TIMESTAMPTZ` | 可空 | 关闭时间 |
| `suspend_date` | `TIMESTAMPTZ` | 可空 | 暂停时间；进入已暂停时记录，离开已暂停时清空 |
| `submitter_name` | `VARCHAR(50)` | 必填 | 提交人 |
| `submitter_dept` | `VARCHAR(100)` | 必填 | 提交部门 |
| `submit_time` | `TIMESTAMPTZ` | 必填 | 提交时间 |
| `creator_id` | `BIGINT` | 可空 | 创建人 |
| `updater_id` | `BIGINT` | 可空 | 更新人 |
| `is_deleted` | `SMALLINT` | 默认 `0` | 删除标记 |
| `created_at` | `TIMESTAMPTZ` | 默认 `NOW()` | 创建时间 |
| `updated_at` | `TIMESTAMPTZ` | 默认 `NOW()` | 更新时间 |

索引：`idx_work_order_status(status, is_deleted)`、`idx_work_order_follower(follower_id)`。问题描述不设唯一索引，允许不同工单使用相同描述。

激活工单时必须填写 1 至 100 字的激活原因，原预计完成时间保持不变。激活后保留上次实际修复时间和处置结果，清空关闭时间，并按原预计完成时间重新判断逾期；激活原因在已解决、已关闭和已暂停状态继续保留，进入待处理或处理中时清空。再次解决时使用新的实际修复时间和处置结果覆盖当前值，历史记录保留每次变更。

| `source_type` | `SMALLINT` | 1 项目，2 需求 | 关联类型 |
| `project_id` | `BIGINT` | 可空，引用 `pms_project.id` | 关联项目 |
| `requirement_id` | `BIGINT` | 可空，引用 `pms_requirement.id` | 关联需求 |
| `task_type` | `BIGINT` | 必填，引用 `pms_archive.id` | 任务类型 |
| `priority` | `SMALLINT` | 默认 1 | 优先级 |
| `status` | `SMALLINT` | 默认 0 | 0 未启动，1 进行中，2 已完成，3 暂停 |
| `is_overdue` | `SMALLINT` | 默认 0 | 是否逾期 |
| `start_date` | `DATE` | 可空 | 启动时间 |
| `expected_end_date` | `DATE` | 可空 | 预计完成时间 |
| `actual_end_date` | `DATE` | 可空 | 实际完成时间 |
| `suspend_date` | `DATE` | 可空 | 暂停时间 |
| `creator_id` | `BIGINT` | 引用 `pms_user.id` | 创建人 |
| `updater_id` | `BIGINT` | 引用 `pms_user.id` | 更新人 |
| `is_deleted` | `SMALLINT` | 默认 0 | 删除标记 |
| `created_at` | `TIMESTAMPTZ` | 默认 `NOW()` | 创建时间 |
| `updated_at` | `TIMESTAMPTZ` | 默认 `NOW()` | 更新时间 |

项目和需求只能二选一。任务最多两层，子任务通过 `parent_task_id` 关联主任务，层级限制由后端校验。每个任务至少关联一名平级负责人，负责人关系存放在 `pms_task_owner`。索引：`uk_task_name_active`、`idx_task_project`、`idx_task_requirement`、`idx_task_parent`、`idx_task_type_status`、`idx_task_expected_end`。

| `status` | `SMALLINT` | 默认 `0` | 0 新建，1 已修复，2 已关闭，3 被激活 |

| `closed_date` | `DATE` | 可空 | 关闭时间 |
| `activation_reason` | `TEXT` | 被激活时必填，最多 100 字 | 最近一次激活原因；后续修复或关闭时继续保留，再次激活时更新 |
| `creator_id` | `BIGINT` | 引用 `pms_user.id` | 创建人 |
| `updater_id` | `BIGINT` | 引用 `pms_user.id` | 更新人 |
| `is_deleted` | `SMALLINT` | 默认 `0` | 删除标记 |
| `created_at` | `TIMESTAMPTZ` | 默认 `NOW()` | 创建时间 |
| `updated_at` | `TIMESTAMPTZ` | 默认 `NOW()` | 更新时间 |

关联项目和关联需求必须按关联类型二选一；“已修复”“已关闭”和“被激活”状态可保留解决方案与修复时间，被激活后再次修复时使用新值覆盖；只有“已关闭”状态保留关闭时间；“被激活”状态必须填写激活原因，后续修复或关闭后继续保留最近一次激活原因。索引：`uk_bug_title_active`、`idx_bug_project`、`idx_bug_requirement`、`idx_bug_assignee_status`、`idx_bug_type_status`、`idx_bug_severity_status`、`idx_bug_created_at`。
