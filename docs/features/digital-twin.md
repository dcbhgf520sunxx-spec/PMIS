# 产品数字孪生

本地入口 `/digital-twin`。侧栏顺序：运维工单 → 数字孪生 → 知识库。

## 本次实现

沿用已确认宝蓝原型，接入当前 PostgreSQL 业务数据。产品切换、八类汇总、十个全景节点、关联来源和明细分页均在 SIDM 原生页面内实现。任务与缺陷分开，缺陷在任务下方，保留弧线和项目右侧留白。当前页面不提供模拟日期回放：系统尚无持久化历史快照，不能用当前字段推算过去结果。原独立模拟原型继续保留；本地可通过下述专用脚本导入明确标记的完整演示产品。

只读接口：`GET /api/digital-twin/products`、`GET /api/digital-twin/:id`。页面每分钟刷新，可手动刷新。查询在只读、可重复读事务内完成，确保同次统计来自同一数据库状态。页面/API/统计/连线路由各自独立文件，后续直接维护该模块。

## 汇总口径

| 分类 | 主指标 | 口径 |
|---|---|---|
| 需求管理 | 需求总量、未结束 | 已完成、已完成未使用、已转项目不计未结束；暂停包含在未结束中 |
| 项目建设 | 项目总量、进行中 | 未开始、进行中、完成、暂停各自去重 |
| 交付计划 | 关键事项、未完成 | 阶段是分组，不与事项数相加；暂停包含在未完成中 |
| 任务执行 | 主任务、未完成 | 主子任务分开；明细保留全部任务，子任务标记；暂停包含在未完成中 |
| 缺陷质量 | 总量、未关闭 | 已修复仍需关闭，被激活是未关闭子集 |
| 合同付款 | 合同总额、待付 | 合同一次计总额，付款按记录计；复用现有合同的分值金额算法；不含维保 |
| 维保服务 | 当期金额、服务中合同 | 当期金额汇总当前日期仍在服务区间的维保合同全额，起止日包含当天、终止日期作为覆盖终点；多份在服合同按金额相加，不按年度摊销。服务中和已结束数量以合同份数表达，概览不再展示未来服务期；已登记但尚未开始的合同仍保留在明细中，不计入当期金额。全景卡片以当期金额为主，合同数量和累计登记金额留在分类明细中，与项目付款分开 |
| 服务工单 | 总量、未解决 | 待处理、处理中、暂停、被激活均为未解决；紧急是未解决子集；工单直接归属产品 |

全景连线表达业务模型关系，即使当前产品某类对象为零也保留该类节点。选中分类可查看统计说明，选中对象显示实际来源链。链路明细各类对象按创建时间倒序展示，同一创建时间按数值编号倒序，分页沿用该顺序。最近7天更新依据记录更新时间，不推断更新字段和金额变化。真实历史和附件进入原业务详情查看。

全景建设实线保留底线，每条实线约 4 个小圆点沿关系起点到终点等间距匀速流动，端点交接时最多 5 个；点数不随线长增加。产品服务虚线直接正向滚动线段，不叠加小圆点。选中节点时高亮关联线。动画用于辅助追踪关系，不代表业务正在执行或产生更新；系统开启减少动态效果时隐藏流动圆点并停止虚线滚动，保留静态关系线。

## 权限和迁移

### AI 总结

最近7天更新区域同时显示 DeepSeek 生成的一段更新总结和原有分类明细。总结以当前用户授权的产品快照为依据，最近7天按读取时刻向前滚动168小时计算，时间统一按上海时区解释，列表展示最新5条，AI仅概括同一批展示记录，不混入7天全量或全景存量统计。总结采用领导简报写法，控制在两句话、60至100字：先提炼近期推进的具体工作，合并同一项目及关联任务，再依据未结束事项的期限和关注标记给出下一步重点建议，不逐条报状态、数量或日期。更新时间只表示记录被修改，不作为这7天内完成、交付或付款事件的证据；缺少成果依据时使用“推进”或“开展”。主任务、子任务及各类金额保持原有口径。

后端 `POST /api/digital-twin/:id/summary` 复用数字孪生菜单权限并重新检查产品和各业务模块权限，前端不能提交自定义提示词或业务数据。调用 DeepSeek 官方 `/chat/completions` 接口，默认使用 `deepseek-flash`、关闭思考模式；真实密钥仅配置在后端 `DEEPSEEK_API_KEY`，模型名称由 `DEEPSEEK_MODEL` 设置，禁止提交到 Git 或返回到前端。参考 [DeepSeek 接口文档](https://api-docs.deepseek.com/api/create-chat-completion/)。

页面每五分钟检查一次，自动检查复用相同用户、产品和证据十分钟内的生成结果。手动“重新生成”和失败重试传入布尔参数 `force: true`，重新检查权限、读取最新业务数据并跳过已完成结果的缓存，生成新总结；同一用户、产品和证据正在生成的请求仍合并，按钮在执行期间禁用并展示生成状态。展示记录变化时立即按新记录生成总结，接口返回记录版本，前端比对版本不一致时先同步快照，不展示错配总结；权限或数据发生变化时不会复用旧结果。模型失败时明确展示失败状态，不以固定模板冒充 AI 结果。不新增数据库表，不写业务变更历史，不产生历史快照；本地密钥和配置不会随 Git 交付到正式环境。

数字孪生菜单单独授权，只默认授予管理员。API先 verifyToken，再 checkPermission('/digital-twin')。原业务模块菜单继续约束对应内容：没有项目权限不返回合同、付款和计划；没有任务/缺陷/工单权限不查询对应内容；没有产品权限拒绝读取产品。受限分类显示“未获授权”，不以零伪装。来源模块未授权时不暴露其名称、ID及链接。

`20261009_01_add_digital_twin_menu.sql` 仅新增菜单/管理员授权及知识库排序，不改表、字段、索引，不改业务数据。初始化 SQL 已同步。版本 v2026.10.09.2 表示准备发布，正式环境未部署。

### 重点事项提醒

业务全景在需求、项目、任务、缺陷、工单节点卡片内部右上角显示可点击的等级数量；没有符合条件的对象或未授权模块不显示提醒。需求、项目、任务使用既有高优先级（2），工单使用高紧急程度（2），缺陷按高严重程度（3）和致命（4）合并数量，以小号椭圆标签“高危 N”显示总数；悬停提示保留各等级数量。提醒只统计未结束对象：需求排除完成、结束和已转项目，项目与任务排除已完成，缺陷排除已关闭，工单排除已解决；暂停、重新激活以及修复后尚未关闭的缺陷仍保留。逾期不自动提升优先级。

任务提醒按对象自身优先级计算，主任务、子任务互不继承；悬停提示分别显示两类数量。点击提醒筛选下方链路明细并显示当前筛选口径和等级列；缺陷标签合并查看未关闭的高和致命缺陷，已有单等级筛选地址仍兼容，创建时间倒序及同时间编号倒序保持不变。点击“查看全部”、普通节点或切换对象恢复该类全部记录；切换产品清除筛选。来源详情返回保留产品、等级筛选、分页和滚动位置。
