# 人员数字孪生

## 组件支撑

部分支持，推荐业务内最小处理。页面复用 TemplateDetailPage / TemplateDetailSection / TemplateDetailTableSection、AdminRangePicker、AdminSegmented filter、AdminSelect、AdminInput、ViewTabs、AdminProgress、StatusTag、OverdueTag 和现有异步反馈。入口及示例为 components/admin、design-system/pages/sections/input/SelectionInputExamples.tsx、sections/BaseSection.tsx、demos/DetailTemplateDemo.tsx。关系图延用 TwinGraph，不新增底座组件。

## 人员、区间与权限

入口 `/digital-twin?view=personal&person=编号&startDate=YYYY-MM-DD&endDate=YYYY-MM-DD`。默认当前登录用户、上海自然月。一个日期区间控件含本周、上周、本月、上月、本季度、本年快捷选择，周从周一开始；自定义两端均包含。不接受完全未来、无效或不完整区间，现有日期服务限制最长3660天。观察日为结束日期与上海今天的较早者。

切换人员保留区间，日期切换保留人员，重置明细页码；刷新和详情返回保留地址条件与滚动。人员选项使用真实 `/user-options`，不使用演示静态人员。

GET `/api/digital-twin/personal`、POST `/api/digital-twin/personal/summary` 接受 personId、startDate、endDate。查询始终按查看者已有业务模块权限读取所选人员；不借用被查看者权限。人员不存在或停用404，非法参数400，菜单拒绝403。原产品视角保持原有统计与总结口径。

## 完成率与关联关系

复用 mcpCompletionAnalysisService 的读取及 evaluateCompletion，不另建计算公式，不修改 MCP 公开输入输出。读取与个人接口处于同一只读、可重复读事务，依赖行只用于判定上级和子任务，不扩大人员工作或泄漏未授权名称。

规则见《个人完成率统计规则》：本期最新计划日期，加期初逾期未完成；只取当前责任角色；任务按个人进行主子任务去重；暂停参与，取消关闭及上级关闭排除，BUG关闭算完成；按各类需求有效结论判断。历史状态及结论截至期末，后期完成不倒算；关键事项按观察日上级项目状态判断逾期与待安排范围，需求后续转项目不抹掉前期有效结论日期；缺少证据显示待核实，待核实事项不得写成已确认进展；无单据的比例为 null，不显示0%或100%。正式统计数量不确定时保留已知数量和核实明细。

参与项目、协作事项也按同一业务区间进行范围判定，但不进入个人完成率；不扩展到他人的下属任务。同一工作优先归负责。历史采用当前责任角色和最新计划日期，不是历史责任或计划快照，也未封存考核结果。无法归期的缺日期工作在排除审计中说明，不伪造日期。

## 页面

个人工作简报为一张自然撑高的卡，不再重复展示两块分类列表。AI以产品为一级分组，每个产品对照本期进展、下阶段需关注，再按项目／业务主题归并总结，不逐张列单据；无模糊的“查看相关工作”入口。以产品为一级区块，产品标题只出现一次，区块内对照本期进展／下阶段需关注，宽屏并排、窄屏上下排列；项目／主题用简短名称引出一句总结，不再铺成多列事项表。不截断正文或限制重要事项数量，删减重复背景与状态，只保留成果、动作、关键日期及阻塞。

本期工作概览六类按菜单顺序：需求、项目、关键事项、任务、缺陷、工单。仅保留展开的关系图，不重复展示顶部统计卡片，也不再放置右侧重复说明。六个节点等高并对齐纳入数、完成率、进度条、已完成／未完成以及遗留、逾期、参与／协作；点击节点或对应数量定位明细。人员中心显示区间和观察日；待核实仍有明确筛选入口，空比例不伪装成0%。未经确认纳入本期的待核实单据不混入本期逾期与高优数量；历史区间不据当前优先级推断历史优先级。

明细主要筛选为全部／已完成／未完成，另有类别、负责／参与／协作、名称／编号／归属搜索、关注标记。待核实与排除清单独立入口。预警复用各模块逾期规则，需求暂停按有效结论判断，不能套用任务的暂停规则。前三类需求的完成依据日期取有效结论记录，不冒用后续实施完成日期。明细每行单行等高，只展示工作事项及当前优先级、直接业务归属、观察日状态、计划完成、完成／结论五列；类别已在筛选中选定，工作名称前不再重复展示单据类型，改用对应模块的优先级标签，缺陷用严重程度、工单用紧急程度；高、中、低均展示，不因已完成而隐藏；关键事项及未提供优先级的记录不伪造标签。优先级悬浮说明标明当前口径，不把当前优先级解释为历史期末值；业务归属复用授权关联链，在名称前标识项目、需求或产品，日常任务单列，缺少归属不根据名称猜测；逾期与业务列表相同，放在名称右侧并按观察日显示逾期天数，不重复挤在状态列。不另列责任关系和重复判定原因。编号、子任务身份、归期与统计依据放在悬浮提示，待核实保留可见标识；长文本由现有表格省略并显示完整提示。标题不重复展示总数。类别默认需求，不提供全部类别；旧链接中的all、缺省或非法类别自动归到需求，无需求权限时选择首个有权限的类别。清除筛选恢复默认类别。列表只展示真实单据，不插入产品、业务线或日期分组行。所有类别取消完成情况排序，已完成／未完成／待核实／排除不再参与排序优先级。需求、项目的全部／未完成视图按计划日期倒序，期初遗留直接参与，无计划置后并按新增时间倒序。任务、缺陷先按直接业务归属名称排列，同名归属按类型与编号区分；工单先按产品名称及编号排列。归属内在全部／未完成视图统一用计划日期倒序（缺陷用新增日期倒序），已完成视图统一用完成／结论日期倒序；不能依据正在比较的两条单据是否完成来切换日期字段，以保证完整排序稳定一致。日常任务独立归属，未关联／未授权归属置后，不根据名称猜测来源。关键事项保持项目计划中的原始顺序：项目编号、阶段sort_order及编号、事项sort_order及编号；前端不按状态、日期或优先级重排，过滤后仍保持原相对位置。无计划仍显示“新增”日期标识，不把新增时间冒充计划；缺少完成日期置后，同日按新增时间、编号倒序稳定排列。逾期、高优只作标记及筛选，不打断对应类别顺序。统计始终基于完整集合，表格只做展示分页。

## 简报证据

收集所选区间、本人填写或最后更新的跟进及真实操作，不把他人跟进归到该人。日期两端包括整天，本期读取截至接口采集时点。同一操作多字段日志合并，无固定事项条数；同一事项全部期间跟进提供模型。阶段容器日志与事项日志按动作区分，避免ID碰撞。

输入包含授权工作描述、期间跟进和判定，操作记录仅用于区间识别及事实版本，不把系统操作播报作为业务内容送入简报；正文不截取前600字，事项不截取前5条。大输入按字符分片、分批处理，批次按产品、项目和证据资格隔离，最多三个批次并行；全部批次完成后分产品再按项目／业务主题提炼，全部事实须审阅，但不要求每条已审阅事实都写入成稿。常规细节留在明细，正文归并实质进展、关键交付及风险，输出引用保留来源编号并校验每批审阅覆盖；结构、覆盖或事实资格不符时纠正一次，仍不符明确失败，不展示部分简报。合并重复表述，不限制条数；不据系统状态编造期间成果，不把待核实或范围外工作当成本期已完成或未完成。

进展来源须有期间跟进或期间有效完成日期；后续行动事实来源须为已确认纳入且未完成；最终归入“下阶段需关注”，与有证据的风险合并；模型输出经过引用和资格校验，但不是业务真实性人工验收。模型配置复用模型中心，凭据不传前端、不写日志。用户已授权所选人员的授权正文及跟进用于同一 DeepSeek 总结，整页时间范围按本轮确认方案调整。缓存按查看者、人员、周期、证据版本和模型隔离，每次复查权限。
