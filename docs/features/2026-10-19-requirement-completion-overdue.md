# 需求逾期与完成率口径统一

用户要求需求逾期按已确认的完成率方法判断。预计完成日期和上海自然日沿用原规则，先判断本轮是否已完成，再判断日期是否已过；逾期指当前仍未完成且超过最新预计完成日期，不另行计算历史完成延误。

- 上会立项、需求提报、预研：有效通过或未通过结论均算完成，后续实施、试运行或暂停保留该结论；重新评估、审批或预研后重新判断。
- 直接实施：已完成、已完成未使用算完成；尚未完成的暂停需求仍参与逾期。
- 已转项目算转交完成；已关闭退出。没有计划日期不参与。
- 后续状态缺少结论历史，或历史不连续时返回空逾期值并标记待核实，不混入已逾期或未逾期筛选。

## 组件支撑情况

全部支持。列表、详情和筛选复用 TemplateListPage、TemplateDetailPage、AdminSelect 和 OverdueTag；待核实使用 AdminTag，示例位于组件工作台 DisplaySection。仅调整业务数据与展示值，不扩展底座。

## 影响范围

完成率的需求完成判定提取至 `requirementCompletionRules.js`，完成率 MCP 与逾期对象计算共用。SQL 查询与筛选使用相同路径定义、状态历史和证据边界，数据库回归对照完成率输出。

需求新增、编辑、状态变更、项目解除关联、i8 同步、列表/详情/相邻记录、定时缓存刷新、MCP基础及周期逾期统计、开放接口共用该口径。个人视角仍在原工作区继续保留，其页面及本地需求逾期适配不纳入本次 Git 交付。

无数据库结构变更，无新增 migration，不批量补写历史结论或修改状态。现有逾期缓存由后续保存及既有定时刷新更新，查询实时计算。本次仅授权 Git 交付，不包含正式发布。
