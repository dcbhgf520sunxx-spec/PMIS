# 列表 Tab 查询条件与统计口径统一设计

## 目标

统一任务、需求和 BUG 列表的 Tab 切换规则，保证在已提交查询条件和后台数据未变化时，仅切换 Tab 不会改变各 Tab 角标。

以任务列表为例：在“全部任务”中选择负责人陈妮后，如果“全部任务”为 6、“我的任务”为 13，那么在两个 Tab 之间切换时角标始终保持 6 和 13。

## 查询条件分类

- 公共查询条件：名称、类型、状态、优先级、逾期、日期等。应用于所有 Tab 的列表和统计。
- 冲突查询条件：任务和需求的负责人、BUG 的指派人。仅在“全部”Tab 显示并限制当前列表；在“我的”Tab 隐藏且不限制当前列表，但保留已提交值，用于“全部”Tab 统计和切回恢复。
- 视图范围：`all`、`mine` 等。由后端根据当前登录用户建立，不能由前端传入用户身份决定。

## 参数和数据流

- 前端始终传递已提交的冲突查询条件：
  - 任务、需求：`filter_owner_id`
  - BUG：`filter_assignee_id`
- 当前为“全部”Tab 时，列表范围同时使用对应查询条件。
- 当前为“我的”Tab 时，后端排除冲突查询条件，并以当前登录用户作为负责人或指派人范围。
- 后端复用 `buildViewQuery` 和 `calculateViewCounts`，使用同一份视图配置生成当前列表、当前总数和所有 Tab 的 `viewCounts`。
- 详情页上一条、下一条查询沿用列表的相同参数和视图范围。

## 交互规则

- 切换 Tab：保留已提交条件和排序，页码回到第一页，清除表格勾选项。
- 隐藏条件：只隐藏，不清除；切回“全部”后恢复显示。
- 未提交草稿：切换 Tab 不自动提交，切回后继续显示草稿。
- 重置：同时清除可见条件和隐藏的冲突条件。
- URL：保存当前 Tab、已提交条件、分页和排序，支持浏览器前进后退及详情返回恢复。

## 影响范围

- 修复任务、需求、BUG 列表及其详情相邻记录查询。
- 项目和运维工单仅回归验证现有正确行为。
- 不修改数据库结构、菜单权限和页面布局，不新增公共组件。
- 保留当前工作区内与 MCP 有关的未提交改动，不纳入本次修改。

## 验收标准

1. 相同查询条件和数据下，仅切换 Tab，各角标保持不变。
2. “我的”列表使用当前登录用户范围，不受隐藏的负责人或指派人条件影响。
3. 切回“全部”后，原冲突查询条件恢复并继续生效。
4. 公共查询条件同时影响所有 Tab 的统计。
5. 重置可清除隐藏条件，条件或后台数据变化后角标正常更新。
6. 切换 Tab 后页码为第一页、排序保留、勾选项清除。
7. 详情页上一条、下一条与来源列表的数据范围一致。
8. 任务、需求、BUG 的接口和页面回归测试通过，项目和运维工单行为不回退。
