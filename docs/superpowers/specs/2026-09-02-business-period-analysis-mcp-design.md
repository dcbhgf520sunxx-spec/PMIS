# 任意周期业务统计分析 MCP 设计

## 背景与目标

现有 SIDM MCP 已提供项目、需求、阶段关键事项、任务、BUG、运维工单、合同和付款的搜索、详情、历史及简单统计能力，但管理日报需要由 Agent 多次分页、逐条读取历史后自行汇总，容易因分页或历史读取不完整产生口径差异。后续管理周报、月报、季报、年报和自定义区间分析也需要共用同一套可靠统计能力。

本次在现有 SIDM 业务查询 MCP 内新增一个只读公共工具 `business_period_analysis`，由后端对授权范围内的真实数据完成任意周期统计、当前风险归并、未来计划、趋势和对比计算。现有明细搜索、`business_get`、`business_history` 和附件查询继续负责下钻核验，不新建 MCP 服务，不改前端，不新增数据库表。

## 范围

### 本次包含

- 支持日、工作日、周、月、季度、年和自定义日期区间。
- 支持实际分析区间、可选计划区间和可选对比区间。
- 支持项目、需求、阶段关键事项、任务与子任务、BUG、运维工单六类工作统计。
- 支持产品、合同和付款的辅助管理分析，但不混入六类工作数量合计。
- 支持期间流量、当前存量、计划展望、趋势、对比、归并、风险候选和完整性说明。
- 复用当前员工身份、菜单权限、公共目录、MCP 审计和结构化返回契约。

### 本次不包含

- 不还原历史某日或历史月末的未完成、暂停、逾期存量。
- 不建设每日状态快照、统计数据仓库或预计算报表表。
- 不分析当前数据模型不存在的正式组织层级、回款、预算、成本、投入产出、验收效果或业务收益。
- 不修改日报、周报、月报或年报的定时任务配置和提示词。
- 不修改现有业务页面、前端组件和写操作 MCP。

## 工具职责与下钻分工

`business_period_analysis` 负责完整统计和发现问题，回答“有多少、发生了什么、趋势怎样、风险集中在哪里”。聚合计算不分页，代表性候选明细可以限量，但必须返回候选总数和是否还有更多。

现有工具保持原职责：

- 业务搜索工具：按分析结果中的条件查询完整分页明细。
- `business_get`：读取单条记录当前详情。
- `business_history`：核验单条记录的完成、计划、人员和状态变化。
- 附件查询：核验交付文件及其他业务附件。

Agent 不得使用明细第一页手工推算全局统计，也不得用聚合候选代替用户明确要求的完整明细。

## 输入契约

工具输入包含：

- `analysis_period`：必填，实际变化统计区间。
- `plan_period`：可选，按当前有效计划日期分析的区间。
- `comparison_period`：可选，对比区间。
- `business_types`：可选，限定业务类型。
- `filters`：可选，限定产品、项目、需求、人员、状态、优先级、严重程度或紧急程度。
- `group_by`：可选，按业务类型、产品、项目、需求、人员、状态、优先级、计划日期或时间桶归并。
- `metrics`：可选，限定需要返回的指标；未传时使用管理分析默认指标。
- `trend_granularity`：可选，`day`、`week`、`month`、`quarter` 或 `year`。
- `detail_limit`：可选，代表性候选明细上限，必须设置安全最大值。

每个周期支持 `day`、`workday`、`week`、`month`、`quarter`、`year` 和 `custom` 预设。非自定义周期使用服务端上海时区、锚点日期和周期偏移解析；自定义周期使用明确的开始、结束日期。响应必须回传解析后的准确区间和实际数据截止时间。

当前存量与风险只以本次服务端执行时点为准，不接受任意历史 `as_of_date`。过去日期的计划区间按当前有效计划日期统计，不声称恢复当时的原始计划版本。

## 输出契约

统一返回：

- `resolved_periods`：解析后的分析、计划和对比日期区间。
- `data_cutoff`：上海时区的实际数据截止时间。
- `period_flows`：期间新增、完成、重要调整、暂停、恢复、激活、重新打开及逾期变化。
- `current_stock`：当前未完成、进行中、暂停和逾期存量。
- `plan_outlook`：计划区间内当前有效计划完成、截至当前已完成和待完成数量。
- `comparison`：与对比区间的绝对变化、分子、分母及可计算时的变化比例。
- `trend`：期间流量的时间分桶趋势；不输出历史存量趋势。
- `groupings`：按允许维度归并的完整统计。
- `quality_and_delivery`：按期、延期、计划调整、阶段交付文件、BUG和工单质量事实。
- `financials`：合同数量和金额、计划付款、实际付款及未付金额。
- `risk_candidates`：按明确业务规则排序的代表性风险候选、候选总数和是否还有更多。
- `coverage`：授权覆盖模块、统计完整性、历史覆盖及不支持维度。

聚合统计失败、必要历史不足或授权模块计算不完整时，返回 `statistics_complete=false`，不得把部分聚合包装成完整结果。

## 固定统计口径

### 六类工作统计

- 新增：有效记录的创建时间落在分析区间。
- 完成：状态在分析区间内真实进入完成终态，同一记录在同一指标中只计一次。
- 重要调整：负责人、协作人、计划日期、优先级或重要状态发生有效变化；普通描述修改、重复保存、普通状态推进和完成不重复计入。
- `became_overdue`：分析区间内进入逾期，不要求当前仍未完成。
- `new_overdue_unresolved`：分析区间内进入逾期，且本次执行时仍未完成。

完成终态固定为：项目已完成；需求已完成或已完成未使用；阶段关键事项已完成；任务和子任务已完成；BUG已关闭；运维工单已解决。BUG已修复、BUG再次激活和工单再次激活分别作为过程与质量指标，不混入最终完成。

子任务保留真实类型标识，但统一进入任务统计行。合同和付款不进入六类工作统计合计。

### 计划和时效

- 计划完成集合以当前有效计划日期落在 `plan_period` 为准。
- 截至当前已完成必须属于计划完成集合且当前处于完成终态。
- 待完成等于计划完成减去截至当前已完成。
- 按期和延期完成使用实际完成日期与当次有效计划日期比较；无法可靠恢复历史有效计划时，必须在覆盖信息中说明。
- 暂停项目下的阶段和阶段关键事项不进入当前逾期、临期、集中交付和人员冲突分析。
- 项目恢复但阶段计划未同步调整时，只形成项目级合并候选。

### 比较和比例

- 对比结果同时返回当前值、对比值和绝对变化。
- 只有对比分母非零且指标适合计算比例时才返回变化比例。
- 完成率、按期率等比例必须返回明确的分子、分母和口径说明。
- 不根据数量、完成率或人员集中评价员工绩效、态度或能力。

## 支持的分析维度

- 时间：日、工作日、周、月、季度、年和自定义区间。
- 业务：业务类型、产品、项目、需求、阶段、父任务和具体记录。
- 人员：负责人、协作人、指派人、跟进人、经办人和创建人。
- 状态：当前状态、状态变化、暂停、恢复、修复、关闭和激活。
- 计划：计划日期、实际日期、调整次数、调整天数、逾期天数和到期分布。
- 风险：当前逾期、临期、暂停、缺少关键字段、交付文件缺失、状态关系异常和集中交付。
- 质量：BUG严重程度、修复、关闭、激活；工单紧急程度、问题类型、解决和激活；阶段交付文件完整性。
- 经营：合同、供应商、合同金额、付款阶段、计划付款、实际付款和未付金额。

需求和工单的提出组织只能作为来源文本分析，不能冒充正式组织层级。MCP 不输出缺少结构化数据支撑的组织、回款、预算、成本、收益和成效结论。

## 权限、安全与完整性

- 工具只对当前员工已授权菜单对应的业务域执行查询和聚合。
- 未授权模块既不返回明细，也不进入合计和分组，响应明确列出实际覆盖模块。
- 输入只允许预定义指标、维度、筛选字段和枚举，不接受 SQL、表达式或任意列名。
- 候选明细保留供内部下钻的业务类型和目标标识，但 Agent 面向普通用户时不得展示内部标识。
- 所有查询复用现有 MCP 调用审计和内容安全处理。
- 统计完整性与候选明细是否截断分别表示，不能因为候选限量把完整统计标为不完整。

## 实现范围

- 新增周期解析与统计服务，集中维护业务域定义、终态、事件字段、计划字段和归并映射。
- 在 MCP `catalog` 注册 `business_period_analysis` 的输入、输出和权限元数据。
- 在查询分发层接入公共工具，复用现有数据库、身份上下文和权限过滤。
- 扩展公共目录、元数据、权限、调用契约和统计服务测试。
- 更新 MCP 接入文档，说明工具用途、输入、输出、统计口径、下钻顺序和不支持范围。

不修改现有明细查询返回契约，不引入新依赖，不执行数据库迁移。

## 验收标准

- 正确处理工作日、周末、跨周、跨月、跨年和闰年日期边界。
- 自定义区间、计划区间和对比区间解析正确且响应回传准确日期。
- 新增、完成、重要调整、逾期、再次激活和重新打开按真实历史去重统计。
- 暂停项目的阶段风险按父项目状态优先规则过滤。
- 权限不足模块不参与统计、合计、分组和候选明细。
- 对比分母为零时不产生无意义比例。
- 趋势分桶合计与相同指标的期间总数一致。
- 候选明细限量不影响聚合总数和统计完整性。
- 过去区间不输出历史存量或历史计划版本结论。
- 分析候选可继续通过现有搜索、详情、历史和附件工具下钻核验。
- MCP 元数据、公共目录、权限、调用契约和后端测试通过。
- `node scripts/verify-change.mjs` 通过，`3103` 健康检查返回 200，`3104` 保持可访问。
