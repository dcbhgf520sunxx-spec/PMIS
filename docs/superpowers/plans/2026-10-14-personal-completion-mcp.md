# 个人完成率 MCP 实现计划

> For agentic workers: 使用 superpowers:executing-plans 在当前会话连续执行。用户已授权实现，不设置分段审批，不进行 Git 提交或生产发布。

**Goal:** 按人员、单据类别和考核期返回有单据与历史依据的个人完成率。

**Architecture:** 业务本体维护规则；新增只读 `business_completion_analysis`，复用现有周期分析的单据SQL、上海日期解析与目标限定历史读取。独立服务执行考核口径，不改变已有周期统计；缺失证据返回待核实，不计算貌似精确的比例。

**Tech Stack:** Node.js、PostgreSQL、现有 MCP SDK 和 Schema 校验，无新依赖。

**Spec:** `docs/个人完成率统计规则.md` 及本对话确认的本体/MCP分工。

## 全局约束

- 保留当前工作区其他修改；无表结构变更、业务记录写入或新权限。
- 当前责任角色和最新计划日期；关闭在观察日排除，暂停参与；历史期末判断不以更新时间推定。
- 项目阶段仅汇总关键事项，个人归属与计划缺失时不推定。
- 聚合读取完整集合；明细分页带数据集指纹，续页变化明确拒绝。
- 执行完整门禁及真实 MCP 登录、发现、成功、参数错误、权限拒绝和审计验证。

## 重点检查

- 上会、审批、预研的否定结论与重新进入评估；后续实施无结论证据。
- 主任务与子任务负责人不同、关闭子任务、全部关闭及每日任务无来源。
- 历史关闭/恢复与上级关闭；历史缺失或不连续时不能输出零完成率。
- 同一BUG一期间多次激活仅统计一次；后期完成不倒算；逾期遗留进入分母。
- 无权限模块、无有效人员身份、明细截断与同数量记录变化。

## 执行任务

Ruling: 历史状态缺失时无法确认是否在期末取消关闭，因此分母也可能不确定；正式完成数/统计数相应返回null，并单列已知数量，避免将缺少证据的单据默认算进分母。
