# SIDM 标准本体建设路径

2026-10-08：按用户明确要求，建设目标调整为可独立验证的标准本体工程。采用 OWL / RDF 表达、标准推理器、SHACL 校验及 SPARQL 查询，不以自定义 JSON 和 JavaScript 规则的结果替代这些交付物。这是本项目选定的标准技术路径，不表示本体工程只有一种方法。

## 原有成果如何使用

业务骨架、字段映射与只读采集能力继续复用。旧JSON本体模型、规则程序、原型测试和旧报告已删除。标准验证仍需使用的两份历史样本保存在`standard/local-output/archived-input/`，与实时数据证据分开。

## 建设顺序及交付

| 步骤 | 具体工作 | 可检查的输出 |
|---|---|---|
| 1. 业务问题与概念模型 | 从已确认骨架提取概念、关系、边界及需要回答的问题；保留待确认事项 | 概念词典、关系说明、问题与预期答案清单 |
| 2. OWL正式建模 | 确定命名空间、类、对象属性、数据属性、逻辑公理及版本；明确采用的OWL范围 | 标准OWL本体文件，可由独立标准工具加载 |
| 3. RDF实例映射 | 将SIDM授权数据映射为带稳定IRI的实例，保留来源、环境、时间与采集范围 | RDF数据文件、映射说明；真实样本与虚构样本分开 |
| 4. 标准推理 | 用支持所选OWL范围的推理器检查一致性及类可满足性，验证预期推导 | 推理器名称与版本、执行命令、推理结果、正例及矛盾反例报告 |
| 5. SHACL数据校验 | 将必填关系、唯一直接归属、格式、跨对象及金额检查写为标准约束；需要时使用SHACL-SPARQL | 约束文件、标准验证报告、故意构造错误的数据与预期结果 |
| 6. SPARQL业务问答 | 在RDF数据及明确的推理结果上执行业务查询 | 查询文件、预期答案、实际结果和对照证据 |
| 7. 接入与复验 | 再由MCP/AI调用标准查询与校验链；保持现有权限与来源追溯 | 接入实现、真实调用证据、版本及回归入口 |

步骤是同一建设任务内部的顺序，不作为逐项征求用户同意的审批节点。正式环境发布及尚未明确的重大业务规则仍遵守项目边界。

## 什么才算标准路径已验证

- 本体文件被独立标准工具实际解析和加载；仅改扩展名不成立。
- 推理器实际运行，对正例得出预期结论，对矛盾反例给出预期结果；不能只证明能加载文件。
- 数据缺项和金额问题由SHACL约束实际识别，不以自写程序的结论充当标准验证结果。
- SPARQL在RDF数据上实际执行，答案与可追溯的来源核对。
- 所有输出标明工具版本、输入数据、执行时间、范围和未验证项；测试数据通过与真实业务样本通过分别报告。

OWL表达业务语义和逻辑，SHACL检查指定数据是否符合要求，两者分工明确。OWL的开放世界语义不会因为未记录来源需求就自动判定矛盾；缺少必填来源的业务检查放在SHACL中，并明确采集范围。OA审批及真实转账不由推理器凭空证明。

## 当前状态

标准工程现已位于 `standard/`：OWL、RDF、HermiT、SHACL、SPARQL核心链路已实际运行，56项标准工程测试通过。详细证据和未完成边界见 `standard/标准路径验证结果.md`。本地现有Query MCP已接入并通过SDK真实数据调用；正式平台HTTP凭据握手及线上发布未执行。现有业务记录未改变，工具调用会写现有MCP审计。

标准依据：[OWL 2](https://www.w3.org/TR/owl2-primer/)、[SHACL](https://www.w3.org/TR/shacl/)。
