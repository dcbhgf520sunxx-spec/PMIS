从业务定义
到有依据的答案

将SIDM真实记录连接起来，推导关联、检查问题，向智能体提供需求与项目、未完成工作、项目合同付款、产品运维合同和工单的查询答案及依据。

业务依据

业务基础

范围、对象、核心关系与已确认业务口径。

总览

当前成果

统一业务定义

完整定义产品、需求、项目、项目阶段、关键事项、任务（含子任务）、BUG、项目合同、付款阶段、付款记录、产品运维合同、运维工单、供应商和人员共14类对象；明确业务含义、直接归属、来源与转化、包含与拆分、供应商关系、人员角色及续签关系，并规定数量、关键属性、状态和共同规则。

关联真实记录

按当前员工权限读取选定产品及项目范围内的SIDM记录，形成可查询的关系网；保留记录标识、来源环境、接口、读取时间和范围。

支持智能体查询

需求与项目：产品下的需求、需求状态及关联项目。

未完成工作：未完成任务、子任务、关键事项及尚未关闭BUG，包含状态分类和责任人员。

项目合同付款：合同金额、阶段计划金额、已登记付款、待付余额、付款情况和读取完整性。

产品运维合同：合同状态、金额、服务期间、供应商、续签及按录入即付款表达的金额与状态。

运维工单：产品工单、当前状态、紧急程度和跟进人。

查询依据：对象标识、来源、读取时间和范围，以及每条答案的校验状态与相关问题。

本体与关系网

本体定义对象、关系和逻辑；真实记录按这套定义形成实例关系网。两者分别是业务模型与具体事实。

当前数字孪生范围

按需读取、生成和查询局部业务关系网；尚未建成全量持续同步、长期保存并可点击浏览的图谱平台。

关键口径已确认定义
需求与项目一条需求可以不转项目；最多一个项目。每个项目只有一个来源需求，二者属于同一产品。
项目与合同项目可以没有合同，最多一份项目合同；项目阶段可选。项目阶段包含关键事项，合同划分付款阶段，两个阶段不是同一种对象。
工作归属任务、BUG只直接归属需求或项目之一，不因转项目自动改挂；主子任务归属一致，当前支持两层；主任务完成时子任务须全部完成。
项目付款OA审批并实际付款后登记付款明细，按阶段和合同汇总已付及待付金额。
运维合同按前后续签管理，不采用并行合同；新合同关联原合同并分别保留服务期间，工单归属产品，不按日期自动绑定合同；录入即表示已付款，金额取合同金额，无单独付款阶段和明细。
人员与状态责任按具体对象确定。各对象的计划、实际日期和状态分别保留，不用关联对象的状态替代。

02

核心路径

标准建设主线

OWL定义业务，RDF连接记录，HermiT推导关系，SHACL检查数据，SPARQL查询答案。

主线

建设路径与成果对应

1OWL定义业务 2RDF连接真实记录 3HermiT推导关系 4SHACL检查数据 5SPARQL查询答案

业务骨架是这五个环节的共同依据，MCP是智能体使用这些能力的入口。交付物直接列在所属环节下。

分工OWL是定义语言；RDF是关系数据；HermiT是推理程序；SHACL是数据检查标准；SPARQL是查询语言。
01

OWL：定义业务

做什么
把已确认的业务对象、关系和逻辑，写成机器可读取的正式模型。
输入
业务骨架中的14类对象、直接关系、可推导关系和明确的逻辑约束。
得到什么
统一的业务模型。它规定对象类别和关系含义，不存放SIDM的全部真实记录。
交付物
  • sidm.ttl存放：OWL类别、关系、属性、逻辑公理、业务注释及版本，使用Turtle格式。用途：维护正式本体主文件。
  • sidm.owl存放：同一模型的RDF/XML格式。用途：供标准工具加载，并与主文件核对等价；不是第二套业务定义。
同一个例子 · 先有规则

任务属于项目，项目归属产品；可以沿着项目，得到任务关联的产品。

02

RDF：连接真实记录

做什么
按业务模型，把授权读取的具体记录表示成“对象—关系—对象或数值”。
输入
选定产品及项目范围内的SIDM记录、字段对照和来源信息。
得到什么
原始RDF实例图：有具体记录、属性和直接关系，保留来源环境、记录ID、接口、读取时间与范围。
交付物

原始RDF实例图 · asserted.ttl：查询时生成，承载本次读取的具体事实。业务数据变化后需要重新读取，不是一份固定的全量本体文件。

实例图及后续推理、校验、答案文件在运行时生成，实时MCP调用使用临时工作目录；不是固定的全量数据文件。接口字段对照和采集程序负责准备数据。

同一个例子 · 放入记录

任务甲 → 属于 → 项目乙
项目乙 → 归属 → 产品丙
任务甲 → 状态 → 处理中

甲、乙、丙为示意名称，仅展示关系形式，不代表实际查询结果。

03

HermiT：推导关系

做什么
按OWL逻辑检查矛盾，并找出原始事实能够推导出的关系。
输入
OWL模型和原始RDF实例图。
得到什么
逻辑检查结果，以及保留原始事实并加入推导关联的RDF图。
交付物

推理后的RDF图 · inferred.ttl：存放原始关系与推导关系，供后续查询使用。

推理报告 · hermit.log：存放逻辑一致性、矛盾与执行信息，供复核使用。

HermiT是运行程序；上述图和报告才是它的输出。

同一个例子 · 得到关联

任务甲 → 关联产品 → 产品丙

任务甲仍直接属于项目乙，不因此改为直接属于产品丙，也不补造来源需求。

04

SHACL：检查数据

做什么
检查记录是否满足必要关系、唯一归属、数量、状态、日期和金额要求。
输入
原始RDF实例图和SHACL检查规则。使用原始数据，避免推导结果掩盖缺项。
得到什么
数据校验结论和问题清单；每个问题关联具体对象与违反的要求。
交付物
  • shapes.ttl存放：必要关系、归属、数量、主子任务、状态、日期和金额约束。用途：统一执行数据检查。
  • 数据校验报告 · shacl.ttl / shacl.txt存放：是否通过、问题对象和违规内容。用途：标明答案中需要核实的数据问题。
同一个例子 · 检查缺项

如果项目乙没有记录来源需求，报告“项目乙缺少来源需求”。任务甲关联产品丙的关系可以成立，同时项目乙存在数据缺项。

05

SPARQL：查询答案

做什么
按照确定的问题，从关系图中查出业务答案。
输入
原始及推理后的RDF数据、查询语句、产品或项目范围。
得到什么
需求与项目、未完成工作、合同及阶段付款、运维合同和工单的结果。工具结合校验报告，为每条答案标记相关问题。
交付物
七份查询文件：存放SPARQL语句，负责不同业务问题；运行后得到结构化查询结果，并由工具整理到answer.json。
查询文件存放内容与用途
requirements.rq产品需求、需求状态及关联项目查询；查清需求与项目的来源关系。
inferred-product.rq工作对象关联产品查询；读取HermiT推导得到的产品关系。
open-work.rq未完成任务、子任务、关键事项及尚未关闭BUG查询；返回状态分类与责任人员。
payments.rq项目合同金额、已读取付款合计、完整性、已付及待付查询；按登记明细汇总合同付款。
stage-payments.rq付款阶段的计划、已付、待付、付款情况及完整性查询；查看分阶段付款。
maintenance-contracts.rq运维合同状态、金额、服务期间、供应商、续签及付款口径查询；按“录入即付款”表达有效合同金额与付款状态。
work-orders.rq产品工单状态、紧急程度和跟进人查询；查看产品问题处理情况。
同一个例子 · 回答问题

查询“产品丙有哪些未完成任务”，可以沿着关联产品找到“任务甲，处理中”。同时保留项目乙缺少来源需求的相关问题。

应用与范围

查询能力、智能体接入分工及当前使用边界。

能力

可用能力

查询内容返回结果
产品需求与项目产品下的需求、关联项目及项目来源。
项目未完成工作指定项目的未完成任务、子任务、关键事项及尚未关闭的BUG；包含状态分类和责任人员。

关系推导通过项目关联任务与产品；从需求查找其关联项目。
数据检查缺少必要关系、归属冲突、任务完成状态不一致、续签日期及付款金额问题。

答案有依据

保留原记录 ID、来源接口、读取时间和查询范围。

问题单独标明

每条答案标记“通过已执行校验”或“异常待核实”，并列出相关数据问题。

使用

智能体通过MCP使用整条链

用户提问 → 智能体确定产品或项目 → Query MCP调用本体服务 → 返回答案、查询范围和数据问题

Query MCP：查

工具为 sidm_standard_ontology_query。使用当前员工权限读取SIDM数据，并调用上述标准组件；智能体整理返回结果。

Action MCP：改

业务数据修改继续通过Action MCP，经过预览、用户确认和执行。本体查询工具只读。

智能体

理解提问、确定范围、选择工具，将返回结果整理为业务答案。

本体服务

装载业务模型，关联数据，运行标准推理、数据检查和查询，标记相关异常。

SIDM

保存业务记录，按员工身份和模块权限提供数据，执行原有业务规则并留下审计。

本机入口Codex另有独立本体MCP复核入口，使用同一标准引擎。SIDM正式接法仍是Query负责查询，Action负责写入。
  • Query-MCP接入说明.md存放：工具参数、输出、权限、错误、审计及智能体使用约定。用途：将标准本体查询接入智能体。
运行关系OWL模型供装载与推理使用；SHACL检查原始图；SPARQL查询原始事实与推导关联。五项有各自分工，不是把同一份文件依次改成五种格式。
范围

当前可用到哪里

本地可用业务模型、授权数据映射、HermiT推理、SHACL检查、SPARQL查询，以及现有Query MCP和本机Codex调用入口。
数据范围按需生成选定产品范围的关系图。未建设全量持续同步和可点击浏览的图谱平台。
答案边界项目付款按登记明细计算；运维合同按录入即已付款表达。金额不代替银行凭证，校验通过只覆盖已建立的规则。
